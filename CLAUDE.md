# Layerd Logo Studio - project memory

Context file for Claude Code sessions on any workstation. Keep it updated when decisions change.

## What this is

Standalone static web tool that generates Layerd brand visuals from the Layerd mark (glass rings) as print-resolution stills and seamless loop videos, each from a deterministic recipe.

- Repo: https://github.com/phildrouet/layerd_logo_studio (owner phildrouet; public for now, may go private)
- Deploy: Netlify site `layerdlogostudio` (https://layerdlogostudio.netlify.app, id `5ee8b706-15ea-4f63-bcf6-e9dc799146e3`), git-linked through the Netlify GitHub App, no build command, publish directory `.`, only `main` builds. GitHub push events never reached the API-created repo link, so pushes deploy through a build hook instead (2026-11-07): the Netlify build hook titled "GitHub push (repo webhook)" (builds `main`), called by a GitHub repo webhook on push events. A push to any branch rebuilds `main`. The build hook's URL (and its id, which is the last part of the URL) is a secret: never commit or print it. If deploys stop, check the webhook's recent deliveries under the repo's Settings > Webhooks. If the repo is ever relinked in the Netlify UI (which registers push events natively), delete the webhook and the build hook to avoid double builds. `netlify.toml` sends `X-Robots-Tag: noindex`; `reference/` is never deployed (gitignored)
- This repo is independent: never reference other projects or repos in it

## Brand

- Swatches: charcoal `#292929`, periwinkle `#6371F7` (primary), lime `#A6E247` (accent only, sparingly: lime light in the mix tints the glass green), pale `#EBEDF5`
- The mark: rings sharing one horizontal diameter (the hinge), tilted about 20, 49 and 68 degrees (outer ring, middle band, centre lens); strokes swell towards the hinge
- Brand typeface: Lazare Grotesk (confirmed 2026-11-07 against the wordmark: "Layerd" sits between Regular and Medium, "AI" between UltraThin and Thin). The copy Phil has is the Befonts trial ("Free for Personal Use", basic Latin letters and digits only, no `( ) : % /`), so it must not be committed, deployed or traced into assets here. Use it only once there is a commercial web licence, and then only with the repo private (a font file in a public repo is redistribution). Until then the UI font stays Aspekta (OFL). Exports carry no typeset text: the wordmark is the logo's own artwork. Logo assets are cropped SVGs converted from the brand PDFs (`reference/brand/`), fills set to the brand hexes
- The wordmark is "Layerd" only, no "AI" (product team, 2026-11-07): the brand files' "LayerdAI" lettering with the A and I paths removed and the viewBox recropped, in both `assets/layerd-wordmark.svg` and the header logo. Cap height and gap are measured on the L, so the lockup proportions below still hold
- Lockups (measured from the brand PNGs, as fractions of the mark's width): horizontal, cap height 0.469, gap 0.233, caps centred on the mark; landscape (stacked), cap height 0.357, gap 0.189, centred under the mark. The mark is 0.934 times as tall as wide

## Priorities (from Phil)

1. All three layouts (Mark, Sphere, Ripple) selectable; Sphere can drift and gather into the logo, with a settable ring count (2026-11-07). Each can be drawn as glass tiles or as a smooth glass ribbon with variable opacity, after the glass ribbons in the LayerdAI PowerPoint template (2026-11-07)
2. "Generate new" compositions on demand, each a deterministic recipe (JSON) that re-renders pixel-faithful at any size; copyable in the UI and exported as a `.recipe.json` sidecar with every export
3. Print-ready exports: A0/A1/A2 portrait+landscape, roller banner 850x2000 mm, 4K/1080p, custom mm+dpi and custom px. Default 300 dpi. RGB PNG only

## Architecture decisions

- `js/presets.js` - parameter model. A recipe is the full params object, `RECIPE_VERSION` 3, merged over defaults on load so partial recipes work; older or foreign recipes (no `rings` block) are rejected with a message. `LAYOUTS` (Mark = `hinged`, Sphere = `stack`, Ripple = `ripple`) set the rings block plus a framing (camera, rotation, focus, aperture, fade); `LOOKS` (Hero, Light) set only colours/materials/lights. Neither touches the other.
- Reading as the logo (2026-11-07): the formed mark only reads as the logo's "eye" with (1) a long, nearly orthographic lens (Mark 24 / 11.8 deg, Sphere 40 / 7.1 deg; close up, perspective pulls the near half of each tilted ring down and the ellipses lose their symmetry), (2) strokes calibrated to the logo front-on (`strokeTop` 0.035 R to `strokeSide` 0.13 R, each band widened by its ring's foreshortening) and (3) periwinkle glass. Fades for the long lens are 60 to 100.
- `js/rings.js` - the geometry. Each ring is one InstancedMesh of annular-sector glass tiles (extruded along local z, so the shader's |normal.z| face/bevel split works) inside a pivot whose local xy is the ring plane. Mark and Sphere share the same rings: radius 2, 3 rows x 110 tiles. The mark pose tilts ring `slot` about the hinge (world x) by `markTilt(k, n)` (curve through the logo's 20/49/68 degrees, signs alternating); the band's front-on stroke follows `strokeTop + (strokeSide - strokeTop) |cos theta|^p` (theta from the hinge), divided by the ring's foreshortening `sqrt(cos^2 theta + sin^2 theta cos^2 tilt)`, so tiles swell as they flow past the hinge and every ring matches the logo front-on. `markAmount` (mean assembly) drives the wordmark fade. The stack pose lays ring j horizontal (a quarter turn about the hinge, on the side it will open to) at height y_j with sphere radius sqrt(R^2 - y^2), drifting on whole-cycle sines; layers map to mark slots by distance from the equator. `assembly(mode, u)` blends the two (off / loop: hold 0-0.15, open 0.15-0.35, drift, gather 0.6-0.85, hold / reveal: gather 0.3-0.75 then hold), staggered per ring; the stack also leans 18 degrees towards the camera until it is the mark. Tangential tile scale follows the radius so rings stay closed while they grow. Ripple builds ~83 rings (one tile row each, alpha-faded outside 70% of the radius) displaced by a radial wave with tiles tilted to the slope. Construction constants live in `RINGS`; changing one changes every image, so bump the recipe version. Glass ribbon (`rings.surface = 'ribbon'`, 2026-11-07): one mesh holds every ring's ribbon in `inner` space, a rounded-rectangle cross-section (`ribbonProfile`, `rings.ribbonThickness` deep, the tile band's width) swept round each ring and rewritten every frame from the same pose as the tiles (`_poseRibbon`; the tiles stay posed but hidden, so focus, clearance and Generate new are unchanged). `sortRibbon` (called from `LogoScene.applyParams` with the un-jittered camera) orders segments back to front across all rings and, within a segment, faces turned away first, so clear glass shows its far surface through the near one; depthWrite stays on so the rings that cross at the hinge resolve. The ribbon shader (`RIBBON_OUT`) writes premultiplied clear glass (blend ONE, ONE_MINUS_SRC_ALPHA): the body colour scaled by the ribbon opacity, reflections and glints at full strength, Fresnel opacity towards grazing angles (Edge shine), and a stylised cyan / periwinkle / pink rim fringe (`ribbonSpectrum`, scaled by Ribbon iridescence) standing in for dispersion. Ribbon colour, opacity, edge shine and iridescence are a `ribbon` block in each look; surface and thickness are geometry and survive layout changes. A smooth ribbon looks the same however far it turns, so Turns per loop is hidden for it, as are the tile-only glass and facet controls (`SURFACE_ONLY` in app.js). Per-tile randomness (facet tint/tilt, drift phases) is a stateless hash of (seed, tile, ring). Shader injection (`makeInjector`) adds the distance fade, IBL gloss split and depth-faded sheen; its string replacements target three r185 chunks, so re-check them on any three upgrade.
- `js/scene.js` - orchestrator. `clocks(p, u)` gives the background clock (`phase.time` swinging by `loop.swing`, periodic in u); the rings take u directly. Seamless loops: rings turn integer `spin` revolutions, drift and the ripple wave run whole cycles, tiles keep their identity (no re-labelling), so u = 0 and u = 1 are byte-identical except in Reveal. `focusDistance` (the object centre for Mark and Sphere, whose open middle would otherwise focus on the far side; the tile nearest the frame centre for Ripple) and `clearance` support Focus on rings and Generate new.
- `js/studio_env.js` - 7 soft radial-falloff light planes plus a wash sphere, baked with `PMREMGenerator.fromScene(env, 0.02)`, re-baked only when the light params change. `js/background.js` - domain-warped fbm on a back-facing sphere (in-scene, so it is consistent under DoF jitter and tiles).
- `js/render.js` - accumulation depth of field: camera jittered on a sunflower aperture disc (aperture = world-unit radius), frustum built manually per sample via `projectionMatrix.makePerspective` from the vertical FOV, with thin-lens shear (focal plane invariant) plus tile window plus subpixel AA jitter. Never use screen-space post (bokeh, tilt-shift, bloom, FXAA): it is resolution dependent and seams under tiling. A soft per-sample highlight cap (default 1.6) stops defocused speculars blooming. Before the cap each sample is sanitised (negative channels to 0, NaN or infinite samples dropped): three's thin-film iridescence occasionally returns a large negative channel at grazing angles, which used to leave black or pure-blue specks in exports. Renderer tone mapping is NoToneMapping; the finish shader does three's ACESFilmic (exposure 1.05) -> sRGB -> text fade -> vignette -> grain. Colours mixed after the curve are display-space: set uniforms with `setHex(n, LinearSRGBColorSpace)` (no conversion), and remember `Color.set('#hex')` already linearises (never add `convertSRGBToLinear`). Half-float accumulation target, 4x MSAA scene target.
- `js/compose.js` - Generate new: 12 candidates from `mulberry32(seed)` using per-layout ranges, each focused on the rings, rendered at 320 px x 4 samples and scored. Two weight sets: `object` (Mark, Sphere: centred light mass, comfortable fill, balance; no thirds or horizon) and `field` (Ripple: highlight on a third, calm horizon, readable foreground). Rejects clearance < 0.7. The winner is written into the recipe; the recipe, not the seed, is the record.
- `js/export_still.js` - 2048 px tiles, 64 samples each, stitched with putImageData; text fade, vignette and grain applied post-stitch in full-frame coordinates (grain uses a JS port of the finish shader's `hash12`), processed in horizontal bands to bound memory (roller banner at 300 dpi is 237 megapixels, near Chrome's canvas area limit; 150 dpi offered and usually right for banners).
- `js/export_video.js` - deterministic frame loop, 24 samples per frame (aperture sequence must be built for 24, not the preview's 64), WebCodecs VideoEncoder (H.264, codec candidates tried high-to-low) + vendored mp4-muxer, fastStart in-memory. MediaRecorder WebM fallback records in real time with a visible note; the `recording` flag in app.js stops the preview loop shrinking the canvas back to preview size mid-capture. The status line says when a Reveal export does not loop. Video length = loop length x 1, 2 or 4 (`loop`, `loop2`, `loop4`; labels show real seconds) or a 5 s test clip; `Loop length` in the video panel mirrors Loop > Duration (controls bound to the same path stay in step), because a hidden Duration made a 30 s clip come out at 15 s (2026-11-07).
- `js/wordmark.js` - the Layerd wordmark (`assets/layerd-wordmark.svg`: the lockup's text paths, viewBox cropped to them, `data-cap-top` / `data-baseline` from the L). `lockupLayout` places it against the projected mark (`LogoScene.lockup`: the ring sphere's outer edge at the hinge) with the brand proportions; with centre on it returns a lens offset and a zoom that fits mark + wordmark inside 84% x 80% of the frame. `render.js` applies offset and zoom to the whole frustum (tiles still meet), and the finish shader composites a texture of the white wordmark rasterised at its on-screen size (preview, video); `export_still.js` draws the coloured SVG on the stitched canvas instead, so print stills stay crisp. Ripple has no mark: the wordmark is centred, 30% of the frame width (the letter size it had at 42% when it read "LayerdAI"). Wordmark colour belongs to the look (Hero pale, Light charcoal).
- `js/app.js` - binds `CONTROLS` (slider / colour / toggle / select) to param paths; `LAYOUT_ONLY` hides ring controls that do not apply to the current layout. The top-bar layout switch calls `applyLayout`. `window.__ts` exposes params, time and the scene for console checks.
- `vendor/` - three.js 0.185.0 (`three.module.js` + `three.core.js`, from npm, licence alongside) and mp4-muxer 5.1.3.
- Preview canvas aspect follows the selected still format, so framing matches the print target. Paused preview refines progressively to 64 samples; playback uses 1 jittered sample per frame.

- 2026-11-07 ribbon checks: Mark, Sphere (5 rings, drift and assembled) and Ripple render as ribbons in Hero and Light; Sphere Loop u=0 and u=1 byte-identical; a 4100 x 2306 ribbon still (3 x 2 tiles) has no seams; Ripple poses and sorts its ~540k ribbon triangles in about 9 ms a frame. Tile renders are byte-identical to before the ribbon work except a handful of formerly negative-sample pixels (1-2 levels)
- Draw order of the ring meshes (fixed 2026-11-07): three sorts transparent meshes by their bounding sphere's centre, and an InstancedMesh computes that sphere once, from the tile poses at whatever frame it is first drawn, then caches it. Overlapping rings therefore drew in an order that depended on which frame the preview had shown after a rebuild, so one recipe could export differently (up to ~90 levels along whole Ripple rings). `_addRing` now gives every ring mesh a fixed sphere round its own centre: Mark and Ripple rings (one shared centre) draw in ring order, inner to outer, every frame; drifting Sphere layers sort by the depth of their centres. Verified: Ripple, Mark and Sphere renders are byte-identical after three different session histories, and loops still close. This changed existing tile renders once: Ripple's near rows show slightly darker seams between rings (inner to outer is the physically right order for the near half of the disc, and the order no longer changes between video frames); Mark changed by a few pixels where rings cross; Sphere renders were unaffected in the cases checked. Never let a cached, pose-derived value decide anything that reaches the pixels
- Hero glass is now the brand periwinkle; Light still needs contrast work, and the lime accent is still to balance
